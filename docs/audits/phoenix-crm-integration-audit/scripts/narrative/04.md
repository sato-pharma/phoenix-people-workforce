# 04 — Integration Dependency Map

How the sidebar modules depend on the integrations, and what breaks when one of them fails.

## The chain

```
Sidebar module (exact)    Function in the app                 Phoenix service / route                 External provider
──────────────            ───────────────────                 ───────────────────────                 ─────────────────
every screen          →   pages, sign-in, data             →  Next.js app on Railway             →   Railway (EX-01)
every screen          →   records, files, sign-in          →  domain services in src/lib          →   Supabase Postgres, Auth, Storage (EX-05/06/07)
Workflow Control      →   nudges, digests, sweeps, drain   →  app/api/cron/* routes              →   cron-job.org (EX-03), Railway loop (EX-02), pg_cron (EX-08)
Email Delivery        →   transactional mail               →  notification outbox + drain        →   Resend (EX-25) → Brevo (EX-26) → Turbify (EX-27)
Telegram              →   alerts and notices               →  notification outbox + drain        →   Telegram Bot API (EX-29)
WhatsApp Templates    →   candidate messages               →  WhatsApp send + webhook            →   Meta WhatsApp Cloud API (EX-31)
Place Checks, My Map  →   address search, routes, maps     →  maps domain service                →   Google Maps Platform (EX-17/18), LocationIQ (EX-19)
Location Integrity    →   case map                         →  browser map                        →   OpenStreetMap public tiles (EX-20)
Fingerprint Report    →   punches → deductions → payroll   →  attendance agent feed              →   ZKTeco agent on premises (EX-40)
Payroll Copilot, SoS Magic, Screening Queue …
                      →   summaries, drafting, sales AI    →  one AI door (src/lib/ai)           →   OpenAI (EX-21) → Anthropic (EX-22) / Groq (EX-23)
CV Database           →   CV intake, archive               →  intake routes                      →   Google Drive (EX-33), Turbify IMAP (EX-27)
Sentry Check          →   error tracking                   →  Sentry SDK                         →   Sentry EU (EX-32)
(no sidebar)          →   deploy, CI, scanners, backups    →  GitHub Actions                     →   GitHub (EX-12/14/15), Google Drive (EX-53)
```

## Where a single failure hurts most

| If this fails | What stops | Fallback today |
|---|---|---|
| Railway (EX-01) | The whole app | Fly.io standby (EX-16) — implemented, never rehearsed (ISS-038) |
| Supabase (EX-05) | The whole app; no point-in-time recovery (ISS-009) | 7 daily backups; nightly off-site copy covers code only (EX-53) |
| cron-job.org (EX-03) | Every scheduled nudge, digest, sweep, intake and the notification drain | The Railway loop covers 5 routes; heartbeats alarm on 20 of 49 jobs (ISS-001) |
| ZKTeco agent (EX-40) | Punches; deductions and payroll are then computed from missing data | None — nothing alarms (ISS-034) |
| Resend (EX-25) | Nothing, if the fallback works | Brevo, then Turbify — Brevo carried real mail this week |
| OpenAI (EX-21) | Nothing, if the fallback works | Anthropic through the same door |
| Google Maps (EX-17) | Address search and place checks | LocationIQ only if switched on (ISS-039) |
