# 02 — Existing Integrations

Every connection between the web app and something outside its own code that the audit could find: hosted services, provider APIs, inbound webhooks, on-premises agents, open-source runtimes the app leans on, and residue of services that were retired. 56 were found.

## How they were found

1. **Code search** across `src/`, `app/`, `scripts/`, `workers/`, `.github/`, `supabase/` and the deployment files for outbound hosts, SDK imports, environment-variable names, webhook routes and scheduled routes.
2. **Configuration reads** — the deployment manifests, the content-security policy, the scheduler registry and the GitHub repository settings.
3. **Live read-only checks** — health endpoints, provider status endpoints that need no credentials or only a read key, database catalogue and delivery-log reads (counts only). No message was sent, no job triggered, no row written (report 13).

The `.env` names were read to learn which integrations are configured; no secret value was copied into this folder.

## Status vocabulary

| Status | Meaning |
|---|---|
| Configured and operational | Code, configuration and live evidence all present |
| Configured but partially operational | Working, with a measured defect |
| Configured but untested | Code and configuration present; no live evidence could be taken without a credential, a billed call or a side effect |
| Implemented but disabled | Code present, switched off |
| Planned but not implemented | Configuration or files present, nothing running |
| Legacy integration / Deprecated | Retired; residue remains |
| Unknown | The production state cannot be read from the repository |
