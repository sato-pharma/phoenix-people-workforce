# 11 — Remediation and Follow-up Register

Every issue the audit found that needs its own correction session. The audit fixed none of them — the constraints forbid changing production, and an unrelated fix during an audit is out of scope.

## Severity

| Severity | Meaning |
|---|---|
| CRITICAL | Active harm now — data loss, money paid wrongly, an open breach. None found. |
| HIGH | Real exposure or a silent failure that touches pay, recovery or security |
| MEDIUM | A defect that degrades a feature or weakens a control |
| LOW | Hygiene: residue, waste, documentation drift |

## The nine HIGH findings, in the order to take them

1. **ISS-023** — close the open secret-scanning alert (rotate first if the secret is live).
2. **ISS-021 / ISS-056** — the repository is public while its runbooks assume it is private; decide visibility knowing that a private repository loses free secret and code scanning (report 05).
3. **ISS-009** — no point-in-time recovery and no rehearsed restore for the payroll database.
4. **ISS-034** — nothing alarms when fingerprint punches stop arriving.
5. **ISS-002** — three daily jobs end in a 30-second scheduler timeout.
6. **ISS-015** — the server fetches applicant-supplied links and follows redirects.
7. **ISS-022** — 92 code-scanning alerts open, 72 high, nothing gating.
8. **ISS-016** — the Migration Drift Check has failed five days running.

Each row names the fix and the recommendation (INT-xxx) that carries it. The "How known" column says where each finding comes from: VERIFIED LIVE (observed in a read-only test in report 13 — 33 findings), FROM CODE (read in the repository — 22), or FROM DOCS / FROM PROJECT RULES (2), with any part that could not be confirmed marked NOT VERIFIED.
