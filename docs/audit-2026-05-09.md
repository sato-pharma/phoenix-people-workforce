# Phoenix Workforce Audit

Date: 2026-05-09
Scope: application code, API surface, auth/session model, Supabase access patterns, SQL assets, frontend reliability, and delivery hygiene
Method: static review of the current worktree plus `npm run lint`

## Top Findings

1. Critical: `resolveAccessContext()` returns `systemAccessContext` when called without a request, which creates an implicit super-admin bypass path for any handler that forgets to pass `request`. Evidence: [src/lib/auth/server.ts](src\lib\auth\server.ts:23).
2. Critical: `app/api/admin/users/bulk` `GET` currently calls `resolveAccessContext()` with no request, so the template export can run as system. Evidence: [app/api/admin/users/bulk/route.ts](app\api\admin\users\bulk\route.ts:257).
3. Critical: session signing falls back to `SUPABASE_SERVICE_ROLE_KEY`, then `DATABASE_URL`, then a hard-coded dev string, so session trust can silently degrade into a weak or reused secret. Evidence: [src/lib/auth/session.ts](src\lib\auth\session.ts:14).
4. Critical: the codebase defaults to service-role Supabase access in server services, which means most data protection depends on app-layer filtering instead of RLS enforcement. Evidence: [src/lib/db.ts](src\lib\db.ts:1), [src/lib/supabase/server.ts](src\lib\supabase\server.ts:19).
5. Critical: dev-header impersonation is available behind `PHOENIX_ENABLE_DEV_AUTH_HEADERS`; if that flag leaks into non-dev infrastructure, callers can self-assert role and HR ID. Evidence: [src/lib/auth/server.ts](src\lib\auth\server.ts:13).
6. Critical: the notification test route becomes open to any caller when `NOTIFICATION_TEST_MODE=true`, and it can send mail to arbitrary recipients from request body input. Evidence: [app/api/notifications/test/route.ts](app\api\notifications\test\route.ts:11).
7. Critical: payroll/expenses/service functions use literal actor names like `"admin"` instead of the authenticated user, weakening auditability. Evidence: [src/lib/payroll/service.ts](src\lib\payroll\service.ts:800), [src/lib/payroll/expenses.ts](src\lib\payroll\expenses.ts:518).
8. Critical: the overview dashboard fabricates financial cost trend values with `Math.random()`, making executive reporting nondeterministic and misleading. Evidence: [src/lib/overview/service.ts](src\lib\overview\service.ts:274).
9. Critical: offer acceptance/rejection is a GET page that mutates server state, making side effects triggerable by link prefetching, scanners, email preview bots, or accidental revisits. Evidence: [app/offers/[token]/accept/page.tsx](app\offers\[token]\accept\page.tsx:10), [app/offers/[token]/reject/page.tsx](app\offers\[token]\reject\page.tsx:10).
10. Critical: offer approval creates employee and compensation records with multiple independent writes and no transaction, so partial hiring states are possible. Evidence: [src/lib/offers/service.ts](src\lib\offers\service.ts:873).

- multiple unused imports/variables that indicate churn and unfinished refactors
