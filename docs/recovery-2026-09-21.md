# The 2026-09-21 session-history recovery — where everything is

**Read this before telling anyone that Claude session history is lost.** The hook that carries the
rule is in [`docs/agents-session-traps-clusters.md`](agents-session-traps-clusters.md) under
**Memory and this index**; the full account of what happened is in
[`docs/agents-session-traps.md`](agents-session-traps.md), "An empty `~/.claude/projects` was read as
*the history is gone*". This file is the pointer to the artifacts themselves.

## What happened, in one paragraph

Two retention keys were added to `~/.claude/settings.json` in the small hours of 2026-09-21, where
**neither had existed before**: `cleanupPeriodDays: 7` at 03:15 and `desktopSessionCleanupPeriodDays: 7`
at 03:17. A sweep under the first at 03:23 removed **1,771 transcripts — 3.877 GB across 628
sessions**, 459 of them in the Phoenix primary folder. That text is unrecoverable: the Recycle Bin
was bypassed (0 items), the Volume Shadow Copy service returns *initialization failure* with no
shadow storage, and there are no System Restore points. It is why sessions after that point felt
like a fresh repo with no memory.

## Why "everything is lost" was still the wrong answer

The sweep touched **one store of three**.

| Store | Holds | Pruned by |
| --- | --- | --- |
| `~/.claude/projects/<slug>/*.jsonl` | the conversation TEXT | `cleanupPeriodDays` |
| `AppData\Roaming\Claude\claude-code-sessions\<accountUuid>\` | one metadata record per session **per account** — title, folder, model, effort, turns, archive state, and every PR that session opened with its branch and merge state | `desktopSessionCleanupPeriodDays` |
| `~/.claude/file-history/<sessionId>/<hash>@vN` | every version of every file a session edited | **neither** |

The second store still held **3,410 records across 8 account folders, 3,631 distinct pull requests,
reaching back to 9 May 2026** — four months earlier than the oldest surviving transcript. All three
pre-relay account folders are the owner's own, confirmed by him on 2026-09-21 ("dc571dfc is my old
account, keep all three"); `~/.claude/relay/accounts.json` only began mapping uuid → email on
2026-09-17, which is why they carried no address and are not strangers.

**It was itself one interactive startup from being swept.** `desktopSessionCleanupPeriodDays: 7`
governs that store exactly, and **2,990 of its 3,410 records were already past the cut** when the
copy was taken.

## The verdict on the code

Every one of the 1,629 recovered file versions was hash-checked against this repository with
`git hash-object` + `git cat-file -e`. **All of them are already in git**, except one 655-byte ad-hoc
test runner from a scratch worktree — and both test functions it ran are registered in the live
`tests/run-tests.ts` today.

**No code, no commit, no branch and no file was lost.** What was lost is the text of the
conversations, and the catalogues below now name 3,410 of them.

the text is not.**

## The one thing still open

Both retention keys are still `7`. Raising or removing either is a `settings.json` edit, which is
**always the owner's own paste** — a session cannot make it, and must never retry it through `sed`,
`node -e` or PowerShell (`automode-allow-cannot-authorize-editing-the-permission-config`). The backup
above means it is no longer urgent.
