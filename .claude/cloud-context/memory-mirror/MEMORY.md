Two traps it surfaced: the marker is itself a `.pdf` token, so leaving it in the scanned text made a yes that matched no real file read as "every file matches" (its own selftest caught that - 29 cases, expect `0 failed`); and `archived 0 []` in the archive log means the file was ALREADY GONE when the hook ran, not that archiving was skipped, so an allowed stand-down is never proof your command is what deleted it.

- [a roll-up can name an ALREADY-MERGED PR as a member](a-rollup-can-name-an-already-merged-pr-as-a-member.md) - it lists whatever was open when it RAN, and was cut from a main without that merge, so merging it REVERTS the work. `mergeStateStatus: CLEAN` cannot see it - cleanly merging an older blob over a newer one is the loss, not a conflict. - [a backtick in a regex literal blinds every comment-only guard below it](a-backtick-in-a-regex-literal-blinds-a-comment-only-guard.md) — `comment-strip.ts` does not track regex literals (its header says so), so one backtick opens a template literal that never closes and 20 comment lines survived the strip; `neutral-wording.test.ts` then named three of that file's own COMMENTS as offenders, pointing at prose the owner ruled out of scope. - [a padded short sha 422s, and a fall-through watcher calls it green](a-padded-short-sha-422s-and-a-fallthrough-watcher-calls-it-green.md) - `gh` prints a 9-char sha; a 40-char one written by padding it exists nowhere, so `check-suites` answers 422 (the error body lands on stdout, so the variable is NOT empty) and `merge-base --is-ancestor` fails for ever, making every "not shipped yet" line uninformative rather than evidence. The compounding fault is the watcher's shape: a loop that `continue`s on a DENY-list of `queued|in_progress|""` matches none of them against the 422 JSON, falls out, and prints its success line - which was relayed as "main's suites all settled clean" when the real state was `in_progress`. Resolve with `git rev-parse <short>`, assert it with `git cat-file -e <sha>^{commit}`, and advance only on an explicit `completed/success`.
- [a selftest probed with the WRONG FLAG reads as "no selftest"](a-selftest-probed-with-the-wrong-flag-reads-as-no-selftest.md) - an absent mode and a mis-invoked one produce the SAME evidence: silence and exit 0. `risky-allow-guard.mjs` dispatches on `--selftest`, the other two pinned hooks on a bare `selftest`, and a sweep for the bare word declared a working 12-case suite absent. - [a C10 refusal is not proof the merge did not happen](a-c10-refusal-is-not-proof-the-merge-did-not-happen.md) - bash-guard C10 refused a `gh pr merge` whose PR a PEER SESSION had merged seconds earlier, and explained itself as "THIS PR IS NOT GREEN YET" when both required checks were green - which points the reader at the PR SIZE and its roll-up options instead of at its STATE.
