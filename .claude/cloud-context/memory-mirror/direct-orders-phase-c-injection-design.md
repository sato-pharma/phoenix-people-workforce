**Phase C = inject approved direct orders into SoS + Weekly, money-critical, idempotent, reversible.** Builds on the merged `codex/direct-orders` branch (PR #1152) which now HAS the `au` schema/attribution engine.

**OWNER DECISIONS 2026-07-19 (override my earlier is_direct=false recommendation):**
1. **"make the engine accept direct and indirect"** — do NOT inject as fake-indirect. Instead MODIFY the money-critical `au` engine so DIRECT sales attribute to the rep (via the pharmacy's area) and COUNT in achievement, keeping `is_direct=true` (direct stays direct). Value stays EXACT because direct rows carry `direct_value` = the sheet `value` (no synthetic-discount hack; inject value = request.sales_value for both bonus & discount).
2. **"Also push into Weekly Sales"** — additionally inject into the weekly_sales pipeline (weekly dashboards), on top of SoS.

**SAFETY INSIGHT (why the engine change is additive, not retroactive):** the manual `Direct` upload is REGION-ONLY (no area_code) → teaching the engine to attribute *direct-WITH-area* only affects NEW module orders (which carry a pharmacy area). Existing rep achievement is unchanged until module orders inject. Manual region-only direct stays unattributed (area NULL → no rep seat).

**ENGINE CHANGES (migration, create-or-replace; staging-first, prove numeric impact):**
- `au.f_monthly_attribution` Branch B (direct): split — direct WITH canonical area → attribute to (line_code, canonical_area) via `au.line_area_map` → rep_seat/dm_seat + occupancy (SAME lateral as Branch A), channel stays `'direct'`, value = `sum(direct_value)`; direct WITHOUT area → keep region-only/no-rep fallback (manual upload).
- `au.f_monthly_achievement`: actuals `where channel='indirect' OR (channel='direct' AND area_code is not null)` so direct-with-area credits the (line,area,product) rep row; area-NULL direct excluded from the rep grid.

**INJECTION (SoS):** is_direct=true rows under NEW distributor_code `DirectReq` (own supersede domain, never touches manual `Direct`), period=sales_month, area_code=pharmacy mapped SoS area, official_line=product line, product_code, client_code=phoenix_pharmacy_code, value=request.sales_value. **Rebuild-per-period from truth**: rebuild the `DirectReq`/month batch from ALL approved-not-reversed orders whose `sales_month` = that period → `phx_finalize_sos_batch` supersedes prior (idempotent + reversible; one batch/month). The trigger is **Finance booking the month** — `setDirectOrderSalesMonth` rebuilds BOTH the old and the new period; an approved order with no booked month injects NOTHING (`phx_rebuild_direct_order_sos_batch` filters on `sales_month = p_period`). Seed `DirectReq` into `source_of_sales_distributors`. Store request.sos_batch_id. See [[direct-order-sales-month-is-finance-owned]].
**Superseded 2026-10-02:** previously "rebuild on each final-approve, period = month of approval" — owner decision 2026-08-03 (PR #1666), golden rule 2026-08-04/08-29: CEO approval never injects; Finance alone books the month.
