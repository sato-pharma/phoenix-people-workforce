DETECTOR HEADER-ROW BUG **SHIPPED-FIX 2026-06-20 (PR #360, e7dd3af8, merged to main + prod 200, deploy success)**: the AI-verification auto-detector (`extractHeaders` in src/lib/sales/distributor-detection.ts) chose the header row as the WIDEST row (most non-empty cells) in the first 10. EGD Branch (EG-BR) export has BLANK columns in its header row (cols 3+4) that every data row fills → a data row is wider than the header → detector read pharmacy names/qty/dates, matched no profile, returned best=null → "couldn't auto-recognize" even though the EG-BR profile maps the file perfectly (the profile-viewer "What the system reads" table is STATIC profile config, NOT live detection — so it always looks correct). Importer (step 2/recognize.ts) worked because it finds headers by NAME match, not cell count — hence the contradiction. Fix: `pickBestHeaderRow(rows, knownHeaders)` picks the row matching the most KNOWN header aliases (union of all profiles), falls back to widest only for unknown files; `collectKnownHeaderAliases()`; `normalizeHeader` now exported from detect-distributor.ts. Proven on the real file (none→high, best=EG-BR) + locked by tests/distributor-detection-header-row.test.ts. RULE: profile-mapping table being correct does NOT mean detection will recognize the file — they're different code paths.
