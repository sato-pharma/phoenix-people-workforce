Reports include Name + Hire Date (owner asked for both).

**KEY GOTCHA — deduction value is null until approval.** CRM/fingerprint governance candidates store `estimated_amount = null`; the money value is only computed on approval (`appliedAmount`, via `calculateDeductionAmountFromBaseSalary` = `base_salary/30 × days` in `deductions-governance/calculations.ts`, NOT locked policy.ts). So a raw report was 53/59 rows = EGP 0. Fix: the export ESTIMATES value for pending day-based rows using the same `base/30×days` formula (via `getBaseSalaryMap`), with a "Value Basis" column = Approved / Estimate / No base salary. After fix all 59 rows valued (live June run total 336,716.68). The on-screen tab still shows "—" for pending (only the export estimates) — a fast-follow would enrich the API JSON too.

**On-screen parity (owner asked 2026-07-07):** the CRM/fingerprint tab now shows each employee's **hire date** under the name and the **specific flagged days** as chips under the day-count (added `hireDate` to the JSON serialization via getHireDateMap keyed by employeeHrIdCompact; `dates` was already returned). The xlsx gained a **"Dates (problem days)"** column (8 cols now: HR ID, Name, Hire Date, Days, Dates, Value, Value Basis, Status). NOTE: for a June run the flagged no-activity dates are in MAY (the FWC cycle window feeding June payroll) — expected, not a bug.
