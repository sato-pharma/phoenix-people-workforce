**What:** A new **NSM-only** employee-portal sidebar tab "Team Calendar" → `/employee-portals/team-calendar`. Shows only the WFC Team Calendar (each rep in the NSM's line as a month grid of field-visit activity); green numeric days deep-link to `/employee-portals/team-calendar/visits/[hrId]/[date]`. NSMs deliberately do NOT hold `hr_calendar`, so the admin WFC surface stays off-limits — this is a separate scoped slice.

Returns whole-company `FieldWorkforceEmployeeSummary[]`; the new service filters to the NSM's line.

**Scoping / access:** `src/lib/employee-portal/team-calendar.ts` — `getNsmTeamCalendar` + `isHrIdInNsmTeamScope`. Line set built via `createPortalSalesLineScope` + `employeeMatchesPortalSalesScope` (same as `getNsmDsmPerformance`), keyed off the NSM's own directory row lineId/lineName. Returns null unless NSM AND a line resolves (never unscoped). Portal API `/api/employee-portals/team-calendar/visits` registered in access-registry as `guard: "domain-helper", permission: null` (role-checked, not a matrix resource) — the coverage test forces domain-helper because there's no assertPermission call.

**CRITICAL BUG caught by user in production 2026-07-05, fixed in PR #834 — MERGED + LIVE** (squash 7437afd4, deploy dpl_9EjW9PKT6tUMRRktxY5RVQ1JD9xt confirmed aliased to phoenix-workforce.vercel.app): #826's DSM grouping actually rendered as one flat undifferentiated name list. Root cause: `toEmployeeReference()` (ireports360-source.ts) never mapped `managerHrId` (only `managerName`) — EVERY employee summary's managerHrId was null company-wide, so no rep could ever match a DSM. Silent because title-based DSM detection still correctly split DSMs into their own (empty) groups while ALL reps fell into one "Other" bucket — looked plausible enough to ship undetected by tests (no test existed for this path). Fix: (1) added the missing managerHrId mapping; (2) replaced brittle title-based classification in buildDsmGroups with real managerHrId-topology grouping (mirrors classifier.ts's existing `orderEmployeesByHierarchy` — exported `buildDsmGroups` from team-calendar.ts); (3) added tests/nsm-team-calendar.test.ts running the REAL classifier pipeline end-to-end, would have caught this. **Lesson: when a reference/DTO builder function looks complete (sets managerName but "forgot" managerHrId), the missing field fails silently as null everywhere downstream — always test end-to-end through the real pipeline, not just the grouping function with hand-built mocks.**

**Also in PR #834**: team/region/area filter dropdowns added per user request. New optional `regionName` field threaded through FieldWorkforceEmployeeReference → toEmployeeReference → classifier → FieldWorkforceEmployeeSummary (live-path-only, like crmIdentity — deliberately did NOT touch archive.ts's DB round-trip to avoid an unrelated migration).
