**What was built:**
1. New Part 1 step `p1_other_deductions` ("Other deductions"), between fingerprint and hold review — 5 categories (CRM, Unpaid Vacation, Day Without Record, Loan, Other) × (days/value/reason) = 15 fields per employee, all independent (HR fills in whichever apply). Days auto-calculates value via Base/30×days client-side (`recommendation-step.tsx` `setDaysValue`); direct value entry works without days. Reason per category, optional. New `StepFieldSpec.kind: "text"` + `StepRow.reasons` added to support this generically.
2. `split.ts` `freezeFirstPart`: new `otherPart1Deductions` (all employees) and `medicalInsurance` (one-part only) params, both subtracted from the frozen First Part — same double-bookkeeping pattern fingerprint already used (also counted once in `assembleParts`'s deduction sum so Second Part nets out correctly).
3. Hire Date now shown as a context column on **every** Part 1/2 wizard step (was previously only on New Hires).
4. Part 1 sheet (`PART1_HEADERS`) gained: Extra Cost of Living, Fuel Allowance, Medical Insurance, Total Deductions, Month Salary (= total monthly salary after deductions), plus Bank Name/Bank Account as computed `extraColumns` (new `ExtraColumn.value` resolver, since bank fields aren't on `SalaryValidationRow` — sourced from `AssembledRow.bankName/bankAccount`, new fields added to that type only, NOT to the canonical payslip row). Full/Part-2 sheet deliberately unchanged.
5. Fixed HR-ID export order: `src/lib/automated-payroll/exports/export-order.ts`, `FIXED_EXPORT_HR_ID_ORDER` (123 entries, owner-pasted list with leading index numbers stripped), `sortForExport()` applied inside `writePayrollWorksheet` — covers every export (Part1, full, finance, and feeds the Salary Changes tab too). Unlisted HR IDs append after the list, stable order.
6. "First Part" column highlighted distinctly (`EXECUTION_FILL`/`EXECUTION_HEADER_FILL`, green) in every export.
7. New "Salary Changes" worksheet tab appended to the Part 1 workbook only: employees whose Net Salary differs from the last **published** run for the prior month, green=increase/red=decrease, only rows with an actual delta. Previous-month lookup via new `draft-store.findPublishedRun` + a `salary_records` query in `run-service.buildRunSheet`.
8. New migration `supabase/migrations/20260724170000_automated_payroll_part1_other_deductions.sql` — 15 add-only columns on `automated_payroll_draft_rows` (`p1od_*`). **Not applied to staging or production** — needs explicit approval per policy before `apply_migration`.
