Owner (Omar) is driving a major "area unification" so ONE canonical geography governs organogram, employee master, employee lifecycle, Source of Sales, and sales calc. DESIGN/CLARIFICATION PhASE — no code, no schema written yet. All work must go to STAGING first, then production only on explicit approval. Related to the earlier reverted attempt [[area-unification-revert-settled]] (#726→#921) — that tried a single global area→region map; this is different (region is per-line, manager-driven).

**THE REAL END GOAL (owner stated 2026-07-12):** today the owner does the monthly closing MANUALLY in the Sales Queue module (hand-calculates, then uploads → the `sales_records` closing pipeline). The whole point of this mapping is to make the **Source of Sales module the AUTOMATIC engine**: once SoS knows per-line `area→rep→manager→region`, it auto-attributes its raw brick/area sales to reps/DMs/regions/lines, auto-runs the monthly closing, and auto-calculates achievements — retiring the manual Sales Queue upload. The 42-area mapping IS the join key between SoS (actuals, geography, no targets) and the manager/target world — the "enabling prerequisite" the audit flagged. Pivot = the AREA (SoS sales per area → line sheet maps area→one rep → manager → region; target attaches per area; achievement per area rolls up). OPEN: where do TARGETS come from now (SoS has none) — must live on the same canonical (line, area) as actuals; does closing feed the LOCKED incentive scheme (scheme-2026.ts); is Sales Queue manual closing removed or kept as transition fallback.

**The canonical model (owner-confirmed via CNS + Pedia line sheets in C:\Users\satoh\Downloads\{CNS,pedia} unificiation.xlsx):**
- **42 fixed areas**, shared identity across all lines. Area codes are region-prefixed (AB1-5, CA1-6, D11-17, D21-26, GZ1-7, OT1-3, UE1-8) but the **code prefix is only the area's fixed identity/label — it NEVER decides the region.**
- Per line, the 42 areas group into **6 regions + 1 "Other"** (NOT 7 regions — the OT prefix IS the "Other"). Number of regions = number of DMs in that line.
- **Org tiers vary by line (owner-confirmed 2026-07-12):** Pedia = 4 tiers NSM→RSM→DM→rep (ONLY line with a Regional Manager layer); CNS + Anti-infective = 3 tiers NSM→DM→rep (no RSM). **DM owns a "region" in ALL lines**; the Pedia RSM is a super-grouping ABOVE the DMs (one RSM owns several regions/DMs). Tree builds via manager_hr_id chain (variable depth, no special flag): rep→DM from the area sheet's Manager column; DM→(RSM if Pedia)→NSM from the employee master's manager_hr_id. Rollup: Pedia gets an extra level (RSM = Σ its regions); CNS/Anti-inf regions roll straight to NSM. OPEN: how many RSMs in Pedia and which DMs (B-74/B-154/B-5/B-94/B-23/vacant-Cairo) report to each — NOT in the area sheet, must come from employee master or an owner-supplied DM→RSM map.
- **Operational region = the area's MANAGER's region, per line, always.** Same area can be in different regions in different lines (proven: Helwan-Maadi = Giza in CNS but Cairo in Pedia; Kafr El-Sheikh 1 code=Delta1 but manager=Alex-BHR in both lines).
- **Team = all reps sharing the same Manager HR-ID** = one region under a District Manager (DM). DM sales+target = Σ his areas (occupied AND vacant).
- **Line/NSM total sales** = Σ(6 region DMs) + Other. **Line/NSM total target** = Σ(6 region DMs) ONLY (Other has no target).

**The 4 (+1) situations per area row in a line sheet (cols: Area Name, Area Code, Medical Rep, Rep HR-ID, Manager HR-ID, Line):**
1. **Occupied** — real rep + HR-ID + manager HR-ID. Has sales + target.
2. **Vacant (will hire)** — rep="vacant", no HR-ID, but HAS a manager. Counts in org structure as a vacant box; still carries sales + target; rolls to its DM. Temporary.
3. **Other, line-specific** — token `<AREA>-<LINE>-OT` (in CNS it's in BOTH rep-name+HR-ID cols; in Pedia only rep-name, HR-ID blank — both mean the same). No manager. Line chose not to staff it, but another line does (Imbaba=Other in CNS, real Giza seat in Pedia; Down town=real in CNS, Other in Pedia). Sales, NO target.
4. **Other, permanent** — rep="Other" (OT1-3: North Sinai, Suez/S.Sinai, Aswan). Other in EVERY line, never staffed. Sales, NO target.
- **(5th) Vacant DM** — Manager HR-ID = free-text label like `"Cairo DM vacant"` (Pedia only so far). The DM SEAT itself is vacant; treat it as a normal DM (its region+areas still carry sales+target, rolls to line/NSM) until a DM is hired. All rows sharing that label = the vacant DM's team (e.g. Helwan-Maadi joins Cairo via this label despite GZ code).

**"Other" must be shown as a first-class pseudo-DM** — its areas listed like medical reps with per-area sales detail + an Other subtotal, then added into the line/NSM total. Never a silent rollup.
