**The core truth (owner-confirmed 2026-06-28, corrected 2026-08-15):** the distributors' weekly sheets are **cumulative from the start of the month**, not standalone weeks — **EXCEPT Direct**, which is invoice-keyed: each Direct sheet carries only that week's own orders, so it must NOT be de-cumulated (`cumulative` flag in `WEEKLY_DISTRIBUTORS`, read only through `weeklyDistributorIsCumulative()`, honoured on BOTH de-cumulation paths — [[direct-is-not-cumulative-but-is-de-cumulated-anyway]]).
**Superseded 2026-10-02:** previously "ALL distributors' weekly sheets are cumulative" — proven wrong for Direct from stored rows and fixed in #2157 (live 2026-08-15).
For the cumulative distributors: e.g. POS/IS-S "12-May" = sales of 1→12 May, "18-May" = 1→18 May; only the first sheet of a month is a true one-week number; resets each month. Proven in stored data: IS-S Sept 2025 climbs 59k→167k→323k→425k then resets to 16k in Oct. The current dashboard sums raw per-sheet values → massive double-count (summing Sept = 973k vs true 424k) and a sawtooth trend. See [[weekly-sales-module-map]].

**Why:** every dashboard number (`loadWeeklyDashboard` in src/lib/sales/weekly/service.ts) sums raw sheets → wrong totals, wrong trend, wrong WoW.

**Agreed solution (build on branch `codex/weekly-sales-logic`):**
1. **Upload wizard** — 3 steps Week → Distributor → Upload. Auto-suggest month + week (1–4) from the sheet's internal date (owner CONFIRMS/overrides on upload — needed for boundary sheets dated the 1st that close the prior month). Same parse/validate/confirm as today. At Validate, show BOTH cumulative (as uploaded) AND "this week only" = cumulative − previous week.
2. **Week tagging** — additive DB columns `cycle_month` + `week_number` on weekly_sales_batches (+ rows for query convenience). Backfill historical batches from their existing week_start date. Keep date-based dedup key (one validated batch per distributor per date).
3. **De-cumulation (READ-TIME, no data rewrite, reversible):** within each (distributor, cycle_month), order sheets by DATE; real week = this sheet − previous-sheet-by-date; first = itself — **only for a distributor whose `weeklyDistributorIsCumulative()` is true; Direct is taken as-is** (see the core truth above). At product×branch grain. **Stock = snapshot (latest), NEVER subtracted.** Flag any negative-week result (means mis-tagged month boundary or duplicate) instead of showing it silently.
4. **Dashboard:** trend = real weekly (no sawtooth); week-by-week comparison table (W2−W1, W3−W2, W4−W3 + % change, totals + breakdown); filters gain **Month** + **Week (1–4)** beside Distributor/Region/Product/Line, all multi-select include/exclude; works WITHIN a month AND ACROSS months ("Both").
5. **Premium XLSX export** — branded, square/slate-900/orange #F97316 design ([[premium-design-language]], [[admin-shell-design-rules]]); bold frozen header rows, autofit spacing, EGP/thousands/% formats; multi-tab; MUST include a **"Report Sources"** block listing every source sheet (distributor · week# · sheet date · cycle month · file · status). Export mirrors the current filter exactly ("anything I filter, I export"). Reuse ExportXlsxButton pattern ([[sos-export-unmapped-and-xlsx-pattern]]).
6. **Completeness tracker** — top of upload page (+ compact on dashboard): month progress bar + Distributor×Week(1-4) grid (✓ with date / overdue reminder / upcoming). Expected by CADENCE (4 weekly; EG/RM/SF = 2 twice-monthly), time-aware. **ADVISORY ONLY — never blocks; late uploads always allowed and flip the cell to ✓ (marked "late").**

**Owner decisions locked:** auto-suggest week (confirm) · mixed cadence (EG/RM/SF twice-monthly) · cap at 4 weeks (5th folds into W4) · week filter Both scopes · twice-monthly week slot auto-from-date · completeness by-cadence + non-blocking.
