**User's locked model (2026-07-04):** the org structure per line is FIXED — every area/territory is a standing seat. Hiring puts a person in the area (filled); resignation empties it (vacant box shows). An employee's lifecycle must NEVER make an area disappear from the organogram. Filled-vs-vacant is decided by **live occupancy**, not by the `position_vacancies.status` field (which import-era data stamped inconsistently — many resigned reps' seats wrongly say `status='filled'`).

**Root cause of "resigned area disappeared" (e.g. Anti infective / Heliopolis under Momen Abdelhady AI-0001):** TWO gates dropped non-open Medical-Rep vacancies before they could render:
1. `src/lib/reports/vacancies.ts` (~line 408) `organogramVacancyRows` filter: `if status==='open' keep; else keep only level!==null && level!=='medicalRep'` — this **excluded every non-open MR vacancy** up front. Fixed to keep any row with a structural level and let occupancy decide.
2. `src/lib/reports/organogram-safety.ts` `suppressFilledVacancyRows`: had `if status!=='open' return false` — blanket-dropped all non-open. Rewrote to occupancy-truth via a SINGLE unified key `seatOccupancyKey = level|line|areaName|manager` for ALL levels (managers AND reps). Rules: drop removed statuses (cancelled/closed/removed); drop manager-level rows with null manager_hr_id AND null replacement (structural debris — killed ~14 fake `PHASE15_...` Cairo DSM rows); else a vacancy shows iff NO active employee occupies its seat key (bool-exists) AND collapse duplicate records for one seat to a single box. **areaName ONLY** — region is never a fallback (a broad region like "Cairo" spans many distinct area seats).
   - IMPORTANT lesson: a first attempt used a TEAM-aware manager slot key (`organogramPositionSlotKey`, broad-Cairo-no-team preserved). That REGRESSED: an active Cairo DSM (Momen AI-0001, area Cairo, team "Cairo") could not match the two stale `B-101` Cairo DSM vacancy records (team NULL), so the chart showed a phantom vacant Cairo DSM next to the hired one. Each DSM owns a DISTINCT area (Cairo/Delta1/Delta2/Giza/…), so **area alone uniquely identifies a manager seat — team matching was both unnecessary and wrong.** Unified area-keyed bool-exists is correct. This also updated MD-8 semantics: an occupied seat now hides ALL its stale vacancy records (was: N-employees-suppress-N-vacancies count-based), and duplicate records for one unoccupied seat collapse to one box.

**Verified against prod (read-only):** fix surfaces exactly the right 8 filled-but-vacant seats (Anti inf: Heliopolis, Cairo East, Alex East 2, Sohag 2; CNS: Cairo East 3/4/5, Nasr City-5th, Port Said; Pedia: Alex Center 2), keeps NASR CITY hidden (occupied by active rep AI-0004), and drops the PHASE15 debris. `line_area_region_map` is NOT the fixed-structure source — it's Source-of-Sales brick geography (AB1/CA1 codes), wrong grain. The de-facto fixed-slot registry is `position_vacancies` (a row per vacated seat) ∪ active employees.

**Resignation service already opens vacancies with `status:'open'`** — the bad `'filled'` statuses are import-era artifacts. The 17 `PHASE15_...` rows (manager_hr_id null, fake names) are test debris safe to delete as hygiene, but the code fix makes them invisible structurally without needing a prod mutation.
