Owner reported `/employee-portals/team-calendar` "data duplicated / visit numbers look doubled" (2026-07-30).

**Diagnosis (all verified live in prod `ozucdzovmcqvepbozvqf`):** NOT the reps — their counts are accurate (rep B-143 shows 23 on Jul 1 = 23 genuinely distinct customers, real Arabic comments). Ruled out (all ~0): canonical HR-ID dups, same-person dup records (national_id/crm_id), reciprocal double rows, duplicate crm_visit_id; burst dups are handled by `collapseDuplicateDoubleVisitSubmissions` (~11 stray rows company-wide). The doubling is the **double-visit CO-CREDIT**: `buildIReports360FieldWorkforceMatrix` credits every double-visit row to BOTH the agent (rep) AND the double partner (manager) — the `credit(agentKey)` + `credit(doubleKey)` path in `src/lib/field-workforce-compliance/ireports360-source.ts`. So every DSM/manager row on the team calendar is a numeric echo of their reps' visits (line-3 DSM B-119 Saad: own_visits=0, ridealong_credit=167 → the calendar showed "167"). Reps have ridealong=0, so they were never inflated. This is BY DESIGN in the shared engine (managers get "worked day" credit so they aren't flagged absent) — only the portal presentation was wrong.

**Fix (owner chose "distinct coaching marker", scoped to portal only):** matrix builder now also returns `ownRegularCountByHrKeyAndDate` (agent-only regular count per day); the live preview builder attaches `cell.ownVisitCount` to VISITS cells (0 = the day is VISITS purely from ride-along). New client-safe pure helpers `portalOwnVisitCount` / `isPortalRideAlongCoachingDay` in `src/lib/employee-portal/team-calendar-cell.ts` (kept out of team-calendar.ts to avoid pulling server code into the client bundle). Portal view `team-calendar-view.tsx`: a pure ride-along day renders a fuchsia **"DV"** marker instead of a number; the number/row-total now reflect each person's OWN visits; a "N DV days" chip is added. Admin FWC + deductions untouched (they ignore the new optional cell field; the `matrix` array is unchanged). Drill-down is already meaningful for DV days — `rep-day.ts` `buildRepDayResult` filters `agentID === id || doubleID === id`, so clicking a DSM's DV day opens the ride-along visits (role="double").
