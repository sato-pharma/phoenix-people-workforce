Deep audit of `/admin/analytics` (Sales Analytics hub: SoS, Monthly Closing, Weekly, Executive Comparison, Reconciliation) done 2026-07-18. Overall ~7.5/10 — strong domain-first architecture; restricted-product lock (LA003/LA004/SS001) is airtight (excluded in SQL views/RPCs AND stripped in TS). The **access model was the weak part**.

**Fixed — PRs OPEN, staging-only, NOT merged:**
- **Finding A** — Weekly analytics leaked the confidential Head Office line: `loadWeeklyFact` + `analytics_weekly_fact` RPC + `analytics.weekly_fact` view never stripped it (the only 1 of 6 line-bearing loaders missing it; the head-office-lock test even pinned `>=5` and omitted weekly). Fix: `canViewHeadOffice` on `WeeklyFilters` + `stripHeadOfficeRows` in loader + thread `canViewHeadOfficeLine(role)` in 3 weekly pages + extend `sales-head-office-lock.test` (`>=6` + weekly page pins). **PR #1124**, branch `codex/weekly-analytics-head-office-strip`, worktree `_wt-weekly-ho-strip`. Restricted products were already safe on weekly (view WHERE).
- **Finding B** — analytics pages apply NO per-viewer line/region scope; safe only because `resolveNavigationMode` routes line-scoped roles to portal. Finance Manager (NONE sales scope, admin-nav, not in any analytics role list) could see unscoped company data by URL. Owner chose **"harden gate now + design phase-2, block Finance Manager."** Fix: new `src/lib/analytics/access.ts` `assertCompanyWideSalesAnalyticsAccess` (throws Forbidden unless `resolveSalesAccessScope().canViewAllSales`; honors `sales_scope_override`; fail-closed), called after `assertPermission` on all 14 pages. **PR #1126**, branch `codex/analytics-company-scope-gate`, worktree `_wt-analytics-scope-gate`. Phase-2 roadmap in `docs/analytics/role-security.md` — **DO NOT relax the gate before loaders are scope-threaded**; by-period/by-area need SQL line/region bounds (line is aggregated away). **#1126 also now folds in finding D**: `assertExecutiveAnalyticsAccess` (CEO/SA/system only, pure) on Exec Comparison + Reconciliation *instead of* the company gate (SFE Manager could reach those 2 by URL); gate test split 12 company / 2 exec. PR retitled "harden page access". Behavioral changes to review: Finance Manager loses analytics entirely; SFE Manager loses Exec/Recon.

- **Finding C** — three config surfaces (sidebar link + `salesAnalyticsPageItems` in system-navigation.ts; `SALES_ANALYTICS_BROAD_ROLES` + Monthly Closing card in hub page.tsx) advertised SoS/Weekly/Closing to NSM/PM/GPM, who are portal-nav + gated out → dead/misleading config. Fix: prune all 6 role lists to Super Admin/CEO/SFE Manager (Exec/Recon stay CEO/SA), + pointer comments to the roadmap. **PR #1128**, branch `codex/analytics-nav-role-prune`, worktree `_wt-analytics-nav-prune`. Zero runtime change (roles never reached the pages). All 5 nav/catalog tests still pass.

- **Findings E + F + G (+ bonus Year fix)** — dashboard cleanup, config/test only, no data change. **PR #1130**, branch `codex/analytics-dashboard-cleanup`, worktree `_wt-analytics-cleanup`. E: removed the dead Batch Status filter (closing_fact is approved-only, so Staged/Rejected returned nothing). F: added `SOS_CUSTOMER_FILTERS` so the Customers tab shows only the period/line/region/customer filters `analytics_sos_by_customer` honors. G: re-pointed `analytics-filter-independence.test` to the LIVE baseline SQL (was reading archived pre-baseline drafts; pre-verified 0 negative-pattern matches). Bonus: removed dead `YEAR_FILTER` from SOS/CLOSING/EXECUTIVE sets (period-scoped RPCs ignore p_year), kept in WEEKLY.

Fix (TS-only, fail-OPEN to code/HR-ID): resolve managerHrId→displayName via employee directory (nickname-aware); clientCode→client_name via `source_of_sales_customer_directory_rollup` (chunked).
