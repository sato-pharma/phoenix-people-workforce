**Methodology note (important, keep for next time):** curl+text-match on a 200 response is NOT reliable for testing Next.js App Router redirects — Next 16 often ships a "soft redirect" (200 status, RSC flight payload containing the target page's serialized data mixed with a `"digest":"NEXT_REDIRECT;replace;<url>;307;"` marker) instead of a raw HTTP 307, when the response has already started streaming. Naive grep for expected page text produces a FALSE POSITIVE (looks like the wrong page rendered) — always grep for the `NEXT_REDIRECT` digest specifically to get the real answer; its presence/absence is unambiguous regardless of streaming quirks.
