Fingerprint Analytics (`/employee-portals/fingerprint-analytics`) + the admin fingerprint report showed NO data because `isAttendanceTrackingEligible` (src/lib/attendance/eligibility.ts) gated tracking to field roles by title ONLY (Medical Rep/DM/RSM). But the office device is punched exclusively by HQ/office staff — so `getFingerprintAttendanceReport` filtered out 100% of punches. Prod evidence (2026-06-20): 17 active device enrollments (all office staff), 3,076 punches, all hidden; last sync was 2026-06-17 (agent runs in irregular bursts — owner deferred that investigation).

**Fix (PR #376, MERGED to main + DEPLOYED to prod 2026-06-20, commit ca06398a):** added `isAttendanceTracked({hasDeviceMapping, jobTitle})` — tracked if actively enrolled on a fingerprint device (new `loadActiveDeviceMappedHrIds()` over `attendance_device_user_map`) OR a field role by title. Wired into fingerprint-report.ts + policies.ts. Verified live: B-10 (HR Manager) API returned 12 real punch-days; page rendered "12 records"; prod domain 200 OK post-deploy. gates green.

**Why:** owner decided office staff ARE the intended target; device enrollment is the authoritative, self-maintaining signal (not job title).

**GOTCHA — two HR_ID normalizers, different casing (caused #382):** `permissions.normalizeHrId` = canonicalHrIdKey = **lowercase**; `attendance/metrics.normalizeAttendanceHrId` = **UPPERCASE**. `loadActiveDeviceMappedHrIds()` keys its Set with the UPPERCASE one. So any `deviceMapped.has(...)` membership check MUST use normalizeAttendanceHrId, not permissions.normalizeHrId (the lowercase one silently misses every entry). fingerprint-report.ts already uses the uppercase one. ilike queries are case-insensitive so they mask this; Set lookups do not.

**Policy effective_from gates historical days:** a per-employee attendance policy only applies from its `effective_from`; days before it fall back to the generic 8h rule → wrongly flagged "Short day". For a standing schedule, backdate `effective_from` to `1900-01-01` (the catch-all sentinel A-3 uses). Done 2026-06-20 for A-8 (Rasha Sabry, GPM): policy id 3 (10:00–16:00, grace 10) effective_from 2026-05-31→1900-01-01 so her May office days reclassify Short→Complete (May 17 stays "Late 22m" — genuine late arrival vs her 10:00 start). attendance_policy_groups table; report recomputes live (no deploy). Editable via in-app policy editor (saveAttendancePolicy).
