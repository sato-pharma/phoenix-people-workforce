All old employee-portal sales dashboards (`/employee-portals/sales`, `/weekly-sales`,
`/monthly-closing`, `/monthly-sales`) were **removed** and rebuilt as a single
**Source of Sales** tab under a new sidebar section "Sales Operations" (2026-06-29).

- Route: `app/employee-portals/source-of-sales/page.tsx`; API: `app/api/employee-portals/source-of-sales/route.ts`; UI: `src/components/sales/portal/portal-sos-dashboard.tsx`.
- Reuses the admin `/sales` engine `getSosDashboard` (distributor SoS, `phx_exec_*` RPCs) via wrapper `src/lib/sales/portal-sos-dashboard.ts` (`getPortalSosDashboard`, `resolvePortalSosScope`).
- Roles: DSM, RM, NSM, PM, GPM, Marketing Manager (`PORTAL_SOS_ROLES` / `isPortalSosRole`). Medical Reps are intentionally EXCLUDED — they no longer have a portal sales dashboard (their personal performance still comes from `v_employee_portal_sales`).
- **Smart-filter rule** (`computePortalSosVisibility`): Region hidden ONLY for DSM (single fixed region); Line hidden for everyone except MM (3 lines). DSM drills by Area. RM region set = his reporting subtree via `isWithinManagerHierarchy`. PM/GPM strictly bounded to assigned `weekly_sales_product_scope` codes — no assignment ⇒ empty (owner decision).
- **LOCKED: Head Office line is confidential** — entire HO line + products are CEO/Super-Admin only (`canViewHeadOfficeLine`, `isHeadOfficeLine`, `stripHeadOfficeRows` in access-scope.ts). Same lock class as LA003/LA004/SS001, fail-closed. **Enforced on ALL sales surfaces** (platform sweep): `getSosDashboard` (rows/options/trend); Weekly (`applyWeeklyAccessScope` via `WeeklyAccessScope.canViewHeadOffice`); Analytics loaders `loadSosByLine/Product/Customer`,`loadClosingByEmployee`,`loadCrossSource` (+ the 9 analytics pages pass `canViewHeadOfficeLine(role)`); SI dashboard (`stripHeadOfficeFromMarketingSnapshot`).
