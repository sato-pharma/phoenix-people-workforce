# Module memory — Git, worktrees and the shared primary checkout

**Scope:** Git mechanics in this repo and the worktrees sessions run in: branches and what a squash merge leaves behind, merging and `gh pr merge`, pushes and refs, which checkout a command is really acting on, husks and retirement, and the ways a parallel session collides with yours. The harness, the laptop and the memory system are `sessions`.

If a rule changed, EDIT its line — never add a second line that contradicts it. - `a-background-poller-dies-with-the-worktree-it-runs-in` — A background poller started with cwd inside a worktree dies the moment you remove that worktree, and a loop that settles on "exit code is not the waiting code" reads the crash as a settled answer — so retiring a worktree can silently convert "still deploying" into a reported success

- `a-merge-mid-session-orphans-your-next-push-silently` — If the owner merges your PR while you are still working, your next push to that branch is orphaned — the PR head stops updating, NO CI fires, and `gh pr checks` keeps reporting the OLD run as green
- `a-no-commit-merge-probe-actually-merges-in-the-shared-primary` — `git merge --no-commit --no-ff` is NOT a dry run — it performs the merge and leaves MERGE_HEAD, so a "would this overwrite anything?" probe mutates the shared primary checkout that every parallel session edits (done 2026-10-02). The real pre-flight is read-only: git diff --name-only HEAD..origin/main plus git ls-files --other --exclude-standard. And never `merge --abort` a shared primary reflexively: first prove the staged name list is identical to HEAD..origin/main with zero unmerged paths, because abort discards anything else.
- `a-reused-branch-name-finds-the-old-merged-pr` — `gh pr list --head <branch> --state merged` answers 'did ANY PR ever merge under this NAME', not 'did THIS work land'. A branch name reused after an earlier PR merged returns the OLD PR, so `new-session.mjs --remove` printed 'PR #3734 merged them — squash residue, not stranded work' for a branch whose own PR (#5089) was still OPEN. Gate a branch deletion on the PR's NUMBER and on the CONTENT being byte-identical on main, never on the branch name.
- `a-squash-merge-makes-a-stacked-branch-rebuild-not-merge` — After a parent PR squash-merges, do NOT merge main into the branch stacked on it — every line of the parent reappears as a conflict. Reset the child to origin/main and re-apply its OWN diff (git diff <parent head> <child head>) with git apply -3.
- `a-worktree-husk-is-pinned-by-the-session-not-its-cwd` — A husk folder that will not delete is held by a PROCESS whose current directory sits inside it - and moving the owning session's cwd does NOT move its already-running child processes, so the folder stays held. The holder IS nameable with scripts/find-worktree-holder.ps1 (it reads each PEB). MSYS /proc sees only MSYS processes, so a bash-only scan reads 'no holder' while claude/node/powershell hold it. Delete is accepted as PENDING and completes later; rename succeeds while delete fails, so rename is not a test for a handle.
