## Rules

- 🔴 **A FINANCE OR BANK FILE IS RECORDED BEFORE IT IS HANDED OUT, AND A RUN WITH A RECORDED DOWNLOAD IS NOT CANCELLED WITHOUT A REASON** (2026-11-13, F-PAY-016). `buildFabSheet`, `buildCibSheet` and `buildFinanceSheet` write a REQUIRED `bank_file_downloaded` audit row before returning the file — a failed write refuses the download. `cancelRun` reads those rows under its claim, before the ledger release, and refuses (409) unless the body carries `overrideDownloaded: true` with a reason of 10+ characters, kept on the `run_cancelled` row; a failed read refuses too. Never make the record best-effort. `bank-file-downloads.ts`, `tests/automated-payroll-bank-file-download-guard.test.ts`.
- 🔒 **EVERY PAYROLL FILE DOWNLOAD WRITES A ROW ON ITS RUN, AND A PERSON TAKES AT MOST 30 AN HOUR** (REC-054, 2026-11-13). `buildRunSheet`, `buildFinanceSheet`, `buildFabSheet` and `buildCibSheet` call `assertPayrollDownloadAllowed` after the role gate and before anything is built, and write ONE row after the workbook is built and before it is returned: the run sheet `file_downloaded` (`recordPayrollFileDownload`, best-effort), the finance sheet and the FAB and CIB files the REQUIRED `bank_file_downloaded` (`recordBankFileDownloaded`, F-PAY-016 — a failed write refuses the file; never make it best-effort), each naming who, the file, the part, the file name, the row count and the role. `listRunDownloads` reads both actions. Past the limit is a readable 429. The run's own "File downloads" panel in the wizard lists them (Super Admin). A new payroll file builder takes both calls. Pinned by `tests/payroll-download-log.test.ts`.
