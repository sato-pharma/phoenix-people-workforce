## Rules

🔴 **`sales-closing.md` IS ALSO LOADED whenever you are here** — its broad `src/lib/sales/*` glob sees

- **SoS attribution is PERIOD-AWARE** — `au.f_monthly_attribution`/`au.f_monthly_achievement` resolve an area's region via `au.f_line_area_map_asof(period_end)`, never today's geography.
- 🔴 **`au.f_line_area_map_asof` FALLS BACK TO THE EARLIEST ROW WHEN NO ROW MATCHES THE DATE** — it is `distinct on (line_code, area_code) … order by (effective_from <= p_asof and (effective_to is null or effective_to > p_asof)) desc, effective_from asc`. So an **in-place** edit of a `line_area_map` row silently reaches **every period before the structure began**, not just today's. Always express a dated change as TWO rows (close the old, insert the new); `au_v_line_area_map` requires exactly one OPEN row per (line, area), and the PK is `(line_code, area_code, effective_from)`. Measured 2026-10-12: an in-place edit of `cns / UE8` would have handed CN-0008 January's Qena 2 target of **92,163.59** and February's **41,509.20**.
- 🔴 **`carries_target` IS A STORED GENERATED COLUMN — "staffed but NOT targetable" cannot be expressed.** It is `area_state = ANY(ARRAY['occupied','vacant_will_hire'])`, so the moment an area leaves the `other_*` family it carries a target. A one-target-per-rep rule is therefore kept **only by never uploading the second area's target**, never by setting a flag. `monthly-targets.ts` and `vs-target.ts` both gate on `.eq("carries_target", true)`, so a target uploaded against an `other_*` area is invisible and uncounted — until that area becomes staffed, when it appears retroactively.
