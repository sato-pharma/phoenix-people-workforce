## Rules

- 🔴 **AN EMPTY FIELD DAY IS NOT A DAY NOBODY WORKED — `read-day.mjs` ASKS `attendance_holiday_overrides` WHETHER THE DAY WAS A DAY OFF, AND CARRIES NO DATE OF ITS OWN.** On Armed Forces Day (Thursday 8 October 2026, moved there from the 6th) the CEO's page said *"15 reps recorded nothing today … which the district managers are following"* — a performance accusation on the one document that leaves the building. The printer is plain `.mjs` and cannot import `@/lib`, so it reads the table `getConfirmedNationalHolidays` → `loadPlanHolidays` uses. 🔴 **Only `observed_date`..`observed_end_date` is the day off — `official_date` is NOT** (6 October is a working day), and the `Day off for <X>` twin confirmed on the same date is never the name a paper prints. A Friday is a day off with no row at all. The read NEVER THROWS, like `loadPlanHolidays`. The day off is stated BEFORE the figures, `AUTHORED` notes are dropped (they are about a day's captures), and a section whose figures are empty is dropped rather than printed as a zero. Pinned by `tests/field-day-report.test.ts`. Account: `docs/field-day-papers.md`.
- 🔴 **AN `AUTHORED` FIELD-DAY NOTE IS KEYED BY CAIRO DAY FIRST, THEN BY REP — `AUTHORED["2026-10-03"]["<rep full name>"]`, never by name alone.** The six hand-written sentences in `print-day.mjs` are the only ones on these papers a human wrote, and each is about ONE day's captures, so it is false on every other day. Keyed by rep alone they printed on every paper that rep ever appeared on: the 3 October note *“The phone was on approximate location all morning”* went out on the 7th, the 8th and after, to a district manager and in summary to the Chief Executive. The `restDay` guard stays behind the day key, not instead of it. Pinned by `tests/field-day-report.test.ts`. Account: `docs/field-day-papers.md`.
- 🔴 **THE ONLY FIELD DAY PRINTER IS `scripts/field-day/print-day.mjs` — BOTH NAMES IN `xlsx/` (`field-day-print.mjs` AND `field-day.mjs`) ARE LAUNCHERS WITH NO LOGIC IN THEM, AND NEVER COPIES.** A copy taken on 2026-10-03 sat in the gitignored `xlsx/` until it was 453 lines stale: it keyed `AUTHORED` by rep name alone and carried none of the 24 `restDay` guards, so a hand-run would have reprinted both defects above onto a district manager's papers and the Chief Executive's summary. `xlsx/field-day.mjs` was the self-contained ancestor behind both, overtaken long before either fix. Both are retired to `F:\Phoenix Workforce\_retired-scripts\field-day-print.mjs.pre-5574`. 🔴 **The launcher SPAWNS and must never `import`** — the printer prints only under its main-module guard, so an import loads it, prints nothing and exits 0, a silent no-op that reads as a clean run. It is tracked through a `!xlsx/field-day-print.mjs` negation in `.gitignore`, so putting logic back shows up in `git status` and in review instead of on paper. The nightly Scheduled Task never comes through it: `run-nightly.mjs` runs the printer from a fresh worktree of `origin/main`. Account: `docs/field-day-papers.md`.
- 🔴 **THE FIELD DAY PRINTER ARCHIVES A PAPER BEFORE REPLACING IT — IT USED TO OVERWRITE IN PLACE, so any verification run silently replaced the PDFs a district manager and the Chief Executive had already been sent.** `run-nightly.mjs` writes straight into the primary's `xlsx/`, and its only match for "backup" is a comment. Measured 2026-10-08: three sessions printed into `xlsx/` within seven minutes, and every `-superseded-pre-NNNN` file that exists was renamed BY HAND. 🔴 **`supersedePaper` copies, and must never rename or delete** — a rename leaves that path empty until Chrome succeeds, and Chrome here exits 0 having written nothing, so a failed reprint would take the owner's only copy with it; a delete is refused outright by `scratchpad-guard.mjs`. The label is the **superseding commit's short sha**, not a hand-typed PR number, and the OLDEST archive for a label wins because that is the paper that went out. The notice rides on STDERR: `run-nightly.mjs` logs every stdout line as a written paper.
- 🔴 **THE ARCHIVE GOES INTO `xlsx/field-day-superseded/`, NEVER BESIDE THE PAPER** (owner, 2026-10-09, after 40 archives had piled up against 28 live papers) — `supersededPathFor` is the ONE place that answers where it goes, because `assertPapersFit` measures that path too: **the archive path is ~41 characters LONGER than the paper's**, so a folder the four papers fit can still be one the copy cannot be written into, where a bare ENOENT would stop the run after the fit check had passed.
- 🔴 **AND THE HOURLY BACKUP WAS WIDENED THE SAME DAY TO FOLLOW IT, on his word** — it used to copy the TOP of `xlsx/` and nothing below, which would have left every archived paper on this one SSD, so `BACKED_UP_SUBDIRS` in `scripts/repo-doctor-xlsx-snapshot.mjs` now names `field-day-superseded/`. **That module repeats the folder name and must NEVER import it:** `xlsx-snapshot.cmd` extracts that file ALONE from `origin/main` and runs it standalone, so any import of another repo file breaks the hourly job outright. The snapshot folder is **flat and keyed by basename**, so a name repeating a top-level one is refused with exit 4, never overwritten. Pinned by `tests/field-day-report.test.ts` and `tests/repo-doctor-xlsx-snapshot.test.ts`. Account: `docs/field-day-papers.md`.

- 🔴 **THE NIGHTLY PRINTS EVERY DAY, A PUBLIC HOLIDAY AND A FRIDAY INCLUDED — NEVER ADD A SKIP BACK WITHOUT HIS WORD** (owner, 2026-10-09, reversing himself the same day: "make the nightly skip a day off" → **"leave the nightly printing on a day off"**; the skip shipped as #5582 and was reverted by #5584). The papers read correctly on a day off since #5573, which is what makes printing them an acceptable answer. 🔴 **AND A `run-nightly.mjs` CHANGE IS INERT UNTIL THE COPY IN `~/.claude/scripts` IS REFRESHED** — the task runs `~/.claude/scripts/field-day-nightly.mjs`, a `Copy-Item` from `install-task.ps1:68`, and only the PRINTER comes fresh from `origin/main`; that gap is why the box never once skipped a day even while #5582 sat on `main`. Refresh it only AFTER the printer it depends on is on `main`, never before: a printer that cannot parse a new flag reads it as the DAY, an invalid date that kills the run and prints nothing at all. Pinned by `tests/field-day-report.test.ts`. Account: `docs/field-day-papers.md`.
