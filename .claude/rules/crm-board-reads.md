## Rules

Moved out of `crm` on 2 Nov 2026 so its injected pointer stays under the 4,000-byte margin
`tests/module-memory.test.ts` enforces (3,849 bytes before the speed root cause's two board-read rules, 4,152
with them). **`crm` keeps every glob it had**, so a session working on these files loads BOTH files — nothing
that used to arrive stopped arriving.

- 🔴 **COUNT A CONTACT'S HISTORY IN SQL** — his iReports360 visits and plan days, never by OFFSET pages over a union view (performance audit, 2026-10-16). `readContactVisitHistory` (`reads.ts`) calls `phx_crm_contact_visit_history` and `loadPlanDatesFor` (`shared-customers.ts`) calls `phx_crm_contact_plan_dates` — one row per contact, the same view, source, contacts and window the app used to fold itself. An OFFSET page over `crm_visits_unified` rebuilds every page before it, so the cost grew with the square of the history. The page walk stays ONLY as the PGRST202 fallback for a database without the function. Migration `20261016180202`.
- 🔴 **ONLY A DISPLAY READER OPTS INTO THE MINUTE-OLD CRM COPY (`reuseRecentWindow: true`).** The owner chose that freshness on 2026-10-16: a dashboard may reuse a copy up to one minute old, and a write the app makes refreshes it at once. The opt-ins today: the SFE Command Center's three reads; the KPIs board's four company reads (call rate with its check-ins, doctor lists, rep KPI reports, and the Phoenix half's visits and check-ins; 23 Oct 2026); the brick-coverage board's company check-in month, which every manager's Command Center, the KPIs pages, the trend and the business review build; the reps-plans rep page's company fallback; and the Phoenix CRM List's check-in pins (next bullet). The door never shares a read narrowed to named reps. `queryVisits`/`queryCheckins` share only the company-window path, keyed on every input (`src/lib/cache/shared-read.ts`, `src/lib/crm/shared-windows.ts`). A saved Phoenix CRM visit and any poll that wrote rows drop the copy, and every door rule still runs after it. A reader that decides money, a deduction, an approval or a notification never opts in. Pinned by `tests/shared-read-cache.test.ts`, which lists the opt-ins by file.
- 🔴 **THE PHOENIX CRM LIST'S CHECK-IN PINS SHARE A COPY UP TO A MINUTE OLD, KEYED BY THE EXACT DOCTOR SET** (production read audit, 28 Oct 2026). `loadObservedPointsFor` (`shared-customers.ts`) made 8,527 calls and 234,221 disk reads over 25–28 Oct. It is display-only: the averaged pin places the address and the map dot and decides nothing. `getOrLoadShared(CRM_OBSERVED_POINTS, …)` keys on the sorted, de-duplicated ids, so a copy holds only the doctors its caller asked for, after that caller's own scope ran — it can never show anyone a doctor outside his list. `refreshSharedCrmWindows` drops it with the windows, and a failed read throws and is never kept. The door's "named reps never share" is about cost (a handful of indexed requests), not safety. Pinned by `tests/shared-read-cache.test.ts` block 13.
- 🔴 **THE REPS LIST'S CHECK-INS AND BRICK NAMES, AND THE KPI PANEL'S OPEN ASSIGNMENTS, EACH COME FROM ONE FUNCTION — NEVER A WAVE OF CHUNKED READS** (1 Nov 2026, the speed root cause: a production read costs ~450 ms at Supabase's edge for 2–7 ms of SQL, so the request COUNT is the lever; the panel's fifteen OFFSET pages per KPI open were the day's heaviest statement, 5,488 pages). `phx_crm_contact_checkins(p_contact_ids)`, `phx_crm_brick_meta(p_brick_ids)` and `phx_crm_open_assignments()` (`20261102010000`) each answer ONE jsonb array of tuples — PostgREST's 1,000-row cap applies to a set-returning function too — and the page walk is kept only as the PGRST202 fallback. The contact ids are a PARAMETER: `= any((select array_agg(…)))` planned a 346 ms full scan of the view. Pinned by `tests/phoenix-crm-board-reads.test.ts`.
- 🔴 **THE REGION → BRICK MAP AND THE TRADE COUNTERPARTIES ARE SHARED COPIES THE WRITES DROP, AND THE KPI PANEL SHARES ITS COPY ONLY WHEN THE CALLER OPTS IN** (1 Nov 2026). `CRM_REGION_BRICK_MAP`, `CRM_TRADE_COUNTERPARTIES` and `CRM_OPEN_ASSIGNMENTS` live in `src/lib/crm/shared-windows.ts` beside the roster: a saved mapping calls `refreshSharedRegionBrickMap`, a direct order or marketing request submitted or decided calls `refreshSharedTradeCounterparties`, and an applied list change drops the open assignments with the roster. `loadPanelRows({ reuseRecentWindow: true })` is for display boards only — the system audit and every decision read live. A write that forgets its refresh leaves a board a minute stale. Pinned by `tests/phoenix-crm-board-reads.test.ts`.
- 🔴 **A DIRECT ORDER OR A MARKETING REQUEST SUBMITTED OR DECIDED DROPS THE SHARED TRADE COUNTERPARTIES (`refreshSharedTradeCounterparties`) BEFORE IT ANSWERS** (1 Nov 2026, the speed root cause). The Reps List board reads which pharmacies trade from a minute-old shared copy (`CRM_TRADE_COUNTERPARTIES`) instead of six whole-table reads per open, so `src/lib/direct-orders/service.ts` and `src/lib/marketing-requests/service.ts` load this module: a write there that forgets its refresh leaves that board a minute stale. Pinned by `tests/phoenix-crm-board-reads.test.ts`.
