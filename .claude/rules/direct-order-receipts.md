## Rules

- 🔴 **A DELIVERY RECEIPT PROVES ONE ORDER FOR EVER — A COMPARE-AND-SET CLAIM, CHECKED ORDER, CUSTODY, CODE, THEN USED** (owner, 26 Nov 2026: "Build the check", "Finance", "14 days"; 27 Nov: "Flag them", "Allow late entry", "make an undo option"). Codes live only in the database and the printed books, never in Git; a wrong code is refused before "already used". A returned book proves only an order approved while its manager held it; from the first hand-out (`receiptRolloutStart`) an order raised with NO book is `no_book` on Finance's desk. Every refused attempt is an order event, never with the typed code. Finance alone (`canManageDirectOrderReceiptBooks`) issues, returns, records lost and cancels pages, and undoes a wrong entry with a reason (`direct_order_release_receipt`). 🔴 The database guards it too (`20261127121951`): never "fix" a guard refusal with a plain update. It gates NO month or collection. Account: `docs/direct-order-receipt-books.md`. Pinned by `tests/direct-order-receipt-books.test.ts`.
- 🔴 **EVERY ORDER HAS TWO ORIGINALS AND A COPY; THE DUE DATES COUNT FROM THE DAY AFTER FINANCE RECORDS THE WAREHOUSE EXIT** (owner, 27 Nov 2026: Original 1 «عهدة» in 3 calendar days, Original 2 signed and stamped by the customer in 6 working days, Friday off). Finance alone records the exit (`recordDirectOrderWarehouseExit`; a correction keeps the old day on the order's history). Original 1 claims the receipt (`recordDirectOrderReceipt`); Original 2 is added once, same serial and code (`recordDirectOrderDelivery`). Until the exit an order is `awaiting_exit` and holds nobody; `has_receipt` only with both originals. A late original blocks that manager's new orders (`listLateReceiptsForRequester` → `submitDirectOrder`, `reviseDirectOrder`, the last approval). The verified print (`/print/direct-order-receipt/<id>`) is Finance's. Pinned by `tests/direct-order-receipt-books.test.ts`.
- 🔴 **AN ORDER STANDS WITHOUT A RECEIPT ONLY WITH THE CEO'S APPROVAL — FINANCE ASKS, THE CEO ALONE DECIDES** (owner, 27 Nov 2026: "صلاحيه عمل اى اوردر بدون ايصال هى صلاحيه انور فقط لاغير موافقه منه والتنفيذ من خلال استاذ احمد"; he chose "Anwar approves in Phoenix"). Finance asks on the order with a reason (`askDirectOrderWithoutReceipt`); `canDecideDirectOrderWithoutReceipt` is role CEO only, deliberately with NO Super Admin override; a refusal says why. An approved order is `without_receipt`: off the missing and no-book lists, no receipt entered on it after. One live ask per order and no edit after the decision, guarded in `direct_order_no_receipt_requests` (`20261127142537`). It still gates NO month or collection. Pinned by `tests/direct-order-receipt-books.test.ts`.
- 🔴 **THE PAPER BOOKS AND THEIR DOCUMENTS: READ THE `direct-order-receipt-books` SKILL FIRST** (owner, 27 Nov 2026: "never forget anything done in this chat") — the printed books, the guides, the sample book and the proposal email. It holds the security marks, the printing conditions, the files in `F:\Phoenix Workforce\Direct Order Receipt Books`, the never-email rules (the full book PDFs and the register carry real codes) and what is still open. The generators are copied into its `generator/` folder.
- 🔴 **EVERY RECEIPT SHEET'S QR IS A PHOENIX LINK, `/r/<serial>-<code>` — A SCAN ASKS FOR A SIGN-IN, THEN A USED RECEIPT OPENS ITS ORDER** (owner, 28 Nov 2026: "كيو ار كود يقرا فينيكس ده اساسي"; "اللي مش هيحط لوجن مش هيدخله"). `app/r/[receipt]/page.tsx` sits outside both shells and redirects to `/admin/direct-orders/<id>`, whose own scope rule decides who sees the order; `decideReceiptScan` checks the code BEFORE the state, so a made-up link learns nothing; the book holder's name is said to Finance and the Administrator only. A photocopy carries the same link, so the one-use claim stays the guard. Pinned by `tests/direct-order-receipt-books.test.ts`.
- 🔴 **AN ORIGINAL COUNTS AT ONCE ONLY WHEN THE SERVER READS ITS QR FROM THE PHOTO; ONE TYPED BY HAND WAITS FOR REVIEW** (owner, 28 Nov 2026: "لايف مش ابلود"; "المالية، وإنت لو المالية دخلته"). Live camera only for a manager; matched → in, another receipt → refused, unread → saved plus a pending `direct_order_receipt_hand_entries` row. Finance reviews a manager's, the Super Admin alone reviews Finance's, never the author; a rejection is one call, `direct_order_decide_hand_entry`, and the manager reads the reviewer's reason word for word (`rejectionToShowManager`; never the closing note on the Original 2 that left with Original 1). Never let an unread photo count. The camera reads whole 2560 x 1440 frames (the phone's own reader, then jsQR) and locks on `stepReceiptQrLock`: a missed frame never undoes a read. Account: `docs/direct-order-receipt-books.md`, "The live camera". Pinned by `tests/direct-order-receipt-books.test.ts`.
