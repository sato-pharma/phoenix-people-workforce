## Memory notes (29)

- `a-class-ratchet-regex-must-allow-a-quote-before-the-ground` — A source ratchet matching `(?:^|[\\s`])border border-…` silently misses every class string that STARTS with the ground — the commonest flat shape — because position 0 is the opening quote, not the class; allow `["`] in the boundary and prove it with a break that turns a lifted template back into a plain string.
- `a-green-test-run-carries-no-type-signal-at-all` — `pnpm run test` uses node --experimental-strip-types, which DELETES types without checking them — a whole suite can go green against code that fails typecheck.
- `a-leaked-fetch-stub-hangs-a-later-test-in-the-shard` — tests/nav-badge-store.test.ts leaves a stub globalThis.fetch (and window/document) for the rest of its process; a test that talks to a real local server through fetch then waits for ever, and a new runTest entry elsewhere decides which tests share that process
- `a-minimized-window-makes-every-browser-test-lie` — A minimized/occluded Chrome window reports visibilityState hidden, which throttles setTimeout to ~1/s and stops requestAnimationFrame entirely - so drag tests, hydration reads and screenshots all return false failures. If no frame is ever forced the page component never hydrates and EVERY click is inert, which reads exactly like a feature you just broke.
- `a-role-probe-cannot-trust-the-http-status-code` — A Next App Router redirect() that fires AFTER the layout has streamed returns 200 with a meta-refresh, not 307 — so a role sweep keyed on status code reads a correct redirect as a successful render
- `a-shard-aborts-at-its-first-failure-so-the-second-cause-is-invisible` — run-tests-sharded dies on the first failing test, so each red shard shows ONE cause and everything behind it never ran — read BOTH shards' FAIL lines before calling a red run diagnosed, and remember a new app/api route is red from its first commit until it is in the access registry.
- `a-sharded-test-jobs-log-tail-is-the-other-shard` — `run-tests-sharded` interleaves two shards into one job log, so the tail is usually the shard that PASSED — read the `[shard N/2]` lines of the failing shard, and the crash sits just before its `PHX_SHARD_RESULT` line.
- `a-test-can-never-hand-a-function-a-process-env-literal` — A function taking an env bag so a test can inject one CANNOT be typed in this app — Next declares NODE_ENV as required on NodeJS.ProcessEnv, and the narrow stand-in hits the weak-type rule from the other side. Take the value, not the bag.
- `abortsignal-timeout-does-not-hold-the-process-open` — Awaiting only the abort of AbortSignal.timeout(n) in a test or script can exit Node with code 13 and no message, because that timer is unref'd and the loop empties.
- `an-exhaustive-record-does-not-gate-the-build-here` — next.config sets ignoreBuildErrors true, so a Record missing a key ships to production — exhaustiveness is NOT a guard in this repo.
- `browser-pane-cannot-preview-scratchpad-files` — Claude_Browser tools can't actually render/screenshot local file:// paths outside the project folder (e.g. the scratchpad dir) in this environment — don't waste turns retrying.
- `choosing-test-suites-by-grepping-your-symbols-misses-the-source-pinning-ones` — Picking which suites to run locally by grepping for the symbols you touched MISSES every test that pins your code by a regex over its SOURCE TEXT — and this repo is full of them, so the subset goes green on a branch the full suite fails
- `correcting-a-wording-goes-red-in-the-sibling-suite-that-pinned-it` — Correcting a refusal or message breaks whichever OTHER suite asserted the old string positively — a hand-picked set of suites is a guess at blast radius, so take it from the import graph with `git grep -ln <module> -- tests` and grep the retired wording across tests before pushing.
- `headless-browser-never-fires-raf-react-suspense-reveal` — A non-compositing browser never fires requestAnimationFrame, so React 19.2 Suspense boundaries never reveal — a correct streamed page looks permanently stuck on the loading spinner.
- `headless-preview-cannot-measure-data-driven-layout` — The headless preview tab's useEffect never fires, so a data-driven layout bug cannot be measured there — an empty page reports zero overflow and looks like a pass.
- `heredoc-eats-backslashes-and-makes-a-test-that-only-passes` — Writing a .ts/.mjs file with `cat > f <<'EOF'` via the Bash tool eats one backslash from `\\\\b` / `\\\\.` / `\\\\s`, in BOTH template and plain string literals, so the built regex matches the wrong thing and the check silently passes.
- `piping-a-test-run-to-tail-destroys-the-verdict` — `node tests/run-tests.ts 2>&1 | tail -20` reports TAIL's exit code (always 0) and keeps only the last 20 lines, so a suite the memory watchdog reaped reads as a clean pass with zero FAIL lines.
- `prove-it-fails-verify-which-assertion-fired` — A regression test only counts if you break the fix and confirm the NEW test's own headline assertion fires — 'the suite went red' has twice been red for the wrong reason
- `run-tests-stops-at-the-first-throw-so-patch-it-to-continue` — `tests/run-tests.ts` rethrows on the first failing test, so one FAIL reports on a PREFIX of 2,200+ tests and each box run buys exactly ONE defect — copy it to `tests/_tmp-continue-runner.ts`, make its catch push the name instead of rethrowing, and run that WITHOUT an env file for the complete failure list in one local pass
- `run-the-affected-tests-directly-instead-of-paying-a-ci-run-per-red` — A branch that adds a count, an event type or a union member breaks SEVERAL exactly-pinned lists, and the suite stops at the first throw — so one CI run reveals one of them; import the affected test files' own run* functions in ONE small node process instead, and NEVER hand-prune the `git grep -l` list, because the file you drop as unrelated is the one that goes red.
- `running-a-phoenix-test-file-directly-runs-nothing` — Running a `tests/*.test.ts` file directly under the alias loader executes NOTHING and exits 0 — the suites are EXPORTED functions that `tests/run-tests.ts` calls, so a standalone run prints no output and passing and failing look identical; import the exported `run<X>Tests` and call it, or run the registry.
- `running-vacation-service-standalone-needs-an-extended-loader` — scripts/alias-loader.mjs cannot load most domain services standalone — it misses next/cache and cannot strip types from the .tsx email templates they transitively import
- `source-pinning-tests-slice-a-fixed-byte-window` — 86 test assertions pin source by slicing a FIXED byte count from a function — growing that function false-FAILS with a regression message that names a regression which never happened.
- `test-seams-for-supabase-backed-code` — How to unit-test Supabase-backed code in this repo — which functions ARE behaviourally testable, why you must never stand up a real client in a test, and the established source-shape convention for DB-backed paging loops
