## Rules

- 🔴 **CV TEXT AND THE SCANNED-CV OCR PAGE IMAGES ARE READ IN A WORKER THREAD WITH A 384 MB HEAP CEILING AND A 30 s DEADLINE (`cv-text-isolation.ts`), AND FREE OCR HAS A 60 s WHOLE-READ DEADLINE** (23 Oct 2026 audit, P5-04). A file past either limit is refused as `unsupported_file`, never retried in-process. A thread that cannot LOAD its library is refused too — `ai_failed`, logged once as `cv_parse_isolation_unavailable`; the in-process fallback is gone (2026-10-26). The thread requires `pdf-parse`, `mammoth` and `word-extractor` BY BARE NAME, so each MUST be in `next.config.ts` `serverExternalPackages` AND `outputFileTracingIncludes` as `./node_modules/<name>/**` — that is what links `/app/node_modules/<name>`; without it every PDF and `.doc` is now REFUSED (it used to take the unlimited fallback). Prove it with `railway ssh` and `require.resolve` from `/app`. Keep `extractRawTextInProcess` in step with the thread. Pinned by `tests/cv-text-isolation.test.ts`, `tests/integration-deadlines.test.ts`.
- 🔴 **THE APPLICATION PDF SIZES A CV BEFORE OPENING IT** (audit, 2026-10-26, point 34). `whatsapp-application-pdf.ts` opens a stranger's CV with pdf-lib, mammoth and sharp in the web process, so `cvRefusedBeforeOpening` leaves out a file over `maxInboundCvBytes()` (the intake's 15 MB knob, never a second number) or a PDF whose plain page objects pass `MAX_APPLICATION_CV_PAGES` (50); pdf-lib's own count, and Chromium's count of a Word file, catch the rest before a page is copied. The sheet is still made, and its footer says why. Pinned by `runWhatsAppApplicationCvCapTests` in `tests/whatsapp-application-print.test.ts`.
