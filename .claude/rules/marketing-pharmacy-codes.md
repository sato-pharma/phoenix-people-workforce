## Memory notes (5)

- `a-wrong-distributor-code-is-a-typo-not-a-rep-gaming-you` — A marketing capture whose distributor code sits in another governorate is a transcription error, not a rep attaching a convenient pharmacy — measured across all 127 validated links: median 23 m, max 1,069 m, zero over 2 km
- `marketing-not-found-codes-have-three-root-causes` — A not_found marketing pharmacy code is usually a WRONG DISTRIBUTOR or a PADDING mistake, not a bad code — chimipharm (and any thin-list distributor) can NEVER match; a stale reference list is the third cause. Placing a shop: the REGISTERED CODE beats GPS for its area (owner 2026-08-21); unresolved → source_of_sales_bricks, never coordinates. AREA grants sight — backfill area_id only, never owners. Traps: reused coordinate, town≠markaz, a dead code is safe to retire.
- `pharmacy-code-numbers-are-not-geographic` — Never identify a pharmacy by picking the numerically nearest distributor code — POS codes are not allocated by area, and a gap-of-1 neighbour was 110km away in a different governorate
- `pos-pharmacy-codes-are-zero-padded` — POS is the only distributor that zero-pads customer codes to 10 digits (61% of the marketing reference DB); compact_pharmacy_code is LIVE on prod 2026-08-16, do not undo
- `the-marketing-code-resolver-never-re-runs` — A marketing distributor code resolved at capture is re-checked nightly only when nobody decided on it (REC-077, 14 Nov 2026); before that it kept its verdict for ever, so a code entered before its pharmacy reaches the sales master reads untrackable long after it became traceable — and validation_notes may carry a signed human verdict that must not be overwritten
