## Rules

- 🔴 **THE MASTER MAP'S HOURLY CHECK REBUILDS NOTHING WHEN NOTHING CHANGED** (24 Oct 2026, from the web process freezing 5 s every 65:00). The sheet's script asks for the plan hourly whatever the stamp says (`Code.gs` `FULL_CHECK_EVERY_MS` on five-minute ticks), and each ask used to reload and rebuild ~74,000 shops on the one thread that serves every page. `payload.ts` now reads the source in full (that read IS the content comparison) and fingerprints it in slices; an unchanged fingerprint reuses the cached tree and plan. `FINGERPRINTED_FIELDS` is typed against every field `loadMasterMapSource` returns, so a new loader input fails the typecheck until it is listed — never loosen that, or a change in it is served stale for ever. Tab hashes are byte-identical to the old one-pass hash (a new hash repaints 4.45 M cells). Slice requests cut from a render kept per snapshot and tab id (`renders`, at most two; a rebuilt snapshot starts empty, so an old tree never answers). Pinned by `tests/master-map-plan-cache.test.ts`.
- 🔴 **A NEW SERVER'S FIRST MASTER MAP PLAN BUILDS THE TREE IN SLICES — the payload takes `buildMasterMapTreeYielding`, never the one-block `buildMasterMapTree`** (14 Nov 2026, the stall alert). With no cached tree the customer merge (~105,000 rows → ~98,500 shops) was ONE block of 1.6–2.6 s on production after every deploy. `mergeSteps` in `customer-merge.ts` is one generator for both callers: the sync merge runs it straight, the yielding one pauses every 2,000 rows; each distinct name is folded once, and sorts use one shared `Intl.Collator` (the same order as `localeCompare`). Same shops, same order, every tab hash unchanged on that morning's production rows; cold plan's longest block 2,953 → 369 ms (laptop). Pinned by `tests/master-map-cold-build-yields.test.ts`.
