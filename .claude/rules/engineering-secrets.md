## Rules

- 🔴 **A JOB THAT READS A PRODUCTION SECRET DECLARES `environment: main-secrets`, WHICH ONLY `main` MAY USE — urgent-deploy.yml uses `urgent-deploy`** (credentials audit, finding 1; owner, 18 Nov 2026: "Fix 1, 3, 4 in one PR"; 19 Nov: "fix those"). Only browser-visible values and `EXPO_TOKEN` stay repository-wide: they are listed in `REPOSITORY_WIDE` in `tests/workflow-secrets-need-environment.test.ts` AND in the `keep` pattern of `move-secrets-to-environments.yml` — change both or neither. ci.yml `validate` stands in main-secrets only on `main` (the staging key and the Telegram pair) and signs with the CI-only literal; deploy-failure-alert.yml hands its message to a `send` job on main, because a Railway deployment's ref is a sha. A job without the environment reads its secret as EMPTY and fails as if the value were wrong. A script that stores a secret runs `gh secret set NAME --env main-secrets`. Account: `docs/security/secret-rotation.md`, "Where the secrets live".
- 🔴 **EVERY `postgres()` CALL IN `scripts/` AND `tests/scripts/` NAMES `ssl: "require"`** (credentials audit, finding 2, 19 Nov 2026). postgres.js connects in plain text otherwise (it ignores PGSSLMODE, and none of our database URLs carries `sslmode`), and the database refuses plain text: SSL enforcement is on since 19 Nov 2026, 02:04 Cairo. An options object declared in the same file counts. psql and pg_dump use libpq, whose `prefer` negotiates TLS; the release gate sets `PGSSLMODE: require`. Pinned by `tests/postgres-connections-use-tls.test.ts`. Account: `docs/security/secret-rotation.md`, "Script database connections ask for TLS".
